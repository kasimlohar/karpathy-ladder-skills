# Sample storyboard — binary search, 90s preview render input

| Shot | Length | Visual | Narration |
| 1 | 10s | Title card: sorted bar array, target marker | You must find one value in a sorted list. A full scan is slow for large data. Binary search halves the range. |
| 2 | 12s | Sorted row, arrows: keep left, keep right | The rule is simple. Order tells you which half to keep. Compare the target with the middle value. Keep only the half that can hold the target. |
| 3 | 12s | Markers Low, Mid, High on the array | Use three markers. Low marks the start of the range. High marks the end of the range. Mid is half way between low and high. |
| 4 | 10s | Mid highlight, compare branch | Check the value at mid. If it matches, stop. If the target is greater, move low up. If less, move high down. |
| 5 | 12s | Example 1 to 15, target 7, mid 8, discard right | Watch an example. Target is seven. Range is one to fifteen. Mid is eight. Eight is greater than seven, so move high down. The range is smaller. |
| 6 | 12s | New mid 4, discard left, range halves | Repeat the step. New mid is four. Four is less than seven, so move low up. The range halves again. Each step discards half of the values. |
| 7 | 10s | Mid 7 match, stop badge | After three steps, mid is seven. It matches the target. You stop the search. Three steps replace up to fifteen checks. |
| 8 | 12s | Log curve, 1M needs about 20 steps | Time grows slowly. Double the size adds one step only. One million items need about twenty steps. That is the power of halving. It needs sorted data. |
